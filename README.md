# Хэндбук: автономная разработка с агентами

## Что это

Это свод моих мыслей и идей по агентной разработке. Я не претендую на полноту, теоретическую точность и глубину. В каждой статье будут ссылки на оригиналы материалов, из которых я брал информацию, так что, если есть желание, в каждую тему можно углубиться самому.

Эта тетрадь не имеет конца, информация тут будет дополняться и обновляться по ходу моего развития в этом направлении. 

## Для кого

В первую очередь - для меня :) Давно хотел собрать всю накопленную информацию воедино. 
Во вторую - для разработчиков, которые активно пользуются агентами (пишут промпты, советуются, дают небольшие задачи), но не знают, куда пойти дальше, как сделать из агента-помощника полноценную боевую единицу. 

## О чём

Тут будут рассмотрены вопросы углубленного использования, поговорим про точную настройку (claude.md/agents.md, rules, skills, hooks), pipeline работы агента (sdd, pdd, tdd и тд), параллельную работу (оркестрация, межсессионная память, worktrees), гейты качества (линтеры, ревью, тесты), эволюцию (обратная связь, ретроспектива).

## Куда иду

Глобальная цель - разработать пайплайн автономной разработки проекта. Агенты сами ищут баги, разбирают их, пишут код, делают ревью, мерджат и выкатывают.

Язык: источник на русском, английская версия - перевод в `en/`, когда главы устоятся.

## Оглавление

*Часть I. Один агент работает хорошо*

1. [Точная настройка](chapters/01-setup.md): системный промпт, инструкции проекта, правила, скиллы
2. Подходы к разработке: SDD, PDD, TDD и прочие DD
3. Задача = PR: малые PR, критерии приёмки, вертикальные срезы
4. Проверка: «готово» значит запуск с выводом, тест на каждый критерий
5. Память между сессиями: трекер как состояние, база знаний, что переживает компакцию

*Часть II. Проект с несколькими агентами*

6. Оркестрация: субагенты, worktrees, общий контекст
7. Контроль качества: хуки, режимы ревью, проверка на регрессии, гейты перед слиянием

Часть III. Система вокруг

8. Разведка до разработки: брать идею, а не реализацию
9. Цена и модели: подписка или API, выбор модели
10. Как настройка меняется: ретро, удаление правил, как пришли к нынешним решениям

## Раскладка

- `chapters/` - файл на главу, появляется, когда глава начата.
- `sources.md` - список чтения: что даёт источник и в какую главу идёт.
